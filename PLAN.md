# Общий буфер обмена (ПК + ноутбук + Samsung S24)

## Цель
Один общий буфер обмена для устройств в домашней Wi-Fi сети:
- скопировал на ПК → можно вставить на ноутбуке / телефоне;
- на телефоне нажал «Отправить» (виджет / плитка / «Поделиться») → текст/ссылка сразу на ПК;
- пришла ссылка на телефон → одно нажатие «Открыть».

## Архитектура: хаб на роутере

```
 [ПК Win11] ──┐
              ├── WebSocket ──► [OpenWrt роутер: clipd] ◄── WebSocket ── [S24 Android]
 [Ноут Win11]─┘
```

Роутер включён всегда и имеет постоянный адрес — идеальный центр.
Клиенты не ищут друг друга, а просто подключаются к `ws://clip.lan:8765`.

### 1. Сервер `clipd` (роутер, OpenWrt)
- Язык: **Go** → один статический бинарник ~5–7 МБ, RAM ~5–10 МБ. Кросс-компиляция под архитектуру роутера.
- Хранит последние N записей (по умолчанию 50) в RAM, опционально сбрасывает в `/tmp`.
- Лимит размера записи (текст — 1 МБ, картинки — 10 МБ, настраивается).
- Рассылает новую запись всем подключённым клиентам кроме отправителя.
- API:
  - `WS /ws` — двусторонний канал (основной).
  - `POST /api/clip` — отправить запись (для curl / ярлыков).
  - `GET /api/clip/latest`, `GET /api/history` — последняя запись / история.
- Авторизация: общий токен (`Authorization: Bearer <token>`), задаётся в `/etc/config/clipd`.
- Автозапуск: init-скрипт `procd` (`/etc/init.d/clipd`).
- DNS-имя `clip.lan` через dnsmasq.

### 2. Клиент Windows (ПК и ноутбук)
- Язык: **Go** (один `.exe`, без установки .NET) либо C#/.NET — решим.
- Живёт в трее, автозапуск с Windows.
- Слушает изменения буфера (`AddClipboardFormatListener`) → отправляет на хаб.
- Получает запись от хаба → кладёт в буфер (с защитой от эха/петли).
- Если пришла ссылка — всплывающее уведомление с кнопкой «Открыть».
- Режимы: авто-синхронизация / только по горячей клавише (напр. `Ctrl+Shift+C`).
- Меню трея: история последних записей, пауза, настройки.

### 3. Приложение Android (Samsung S24)
- **Kotlin + Jetpack Compose**, виджет на **Glance**.
- Ограничение Android 10+: приложение в фоне **не может читать** буфер. Поэтому
  отправка с телефона — по явному действию:
  - **Виджет** на рабочем столе: последняя запись + кнопки «Отправить мой буфер», «Копировать», «Открыть».
  - **Плитка в шторке** (Quick Settings Tile) «Отправить буфер».
  - Пункт в меню **«Поделиться»** (ссылки из браузера, текст из любого приложения).
- Приём: foreground-сервис с WebSocket, пишет в буфер телефона (запись в фоне разрешена) и
  показывает уведомление с кнопками «Копировать» / «Открыть ссылку».
- Экономия батареи: сервис подключается только в домашней Wi-Fi сети.

### Протокол (JSON по WebSocket)
```json
{ "type": "clip", "id": "uuid", "from": "pc", "kind": "text|url|image",
  "mime": "text/plain", "data": "...", "ts": 1727350000 }
```
Также `hello` (регистрация устройства), `ack`, `ping/pong`, `history`.

## Этапы
1. **MVP сервер** `clipd` + тестирование curl/websocat. Сборка под роутер.
2. **Windows-клиент**: текст/ссылки, трей, авто-синхронизация.
3. **Android**: сервис + уведомления, «Поделиться», плитка, виджет.
4. **Расширения**: картинки, история, горячие клавиши, (опц.) шифрование, файлы.

## Что нужно уточнить
- Архитектура роутера: вывод `uname -m` и `cat /etc/openwrt_release`.
- Синхронизация на ПК: автоматически при каждом копировании или по горячей клавише?
- Только текст/ссылки, или сразу картинки (скриншоты)?
