# clipd — сервер общего буфера (роутер)

Работает на роутере **GL.iNet Beryl AX (GL-MT3000)**, хранит историю буфера и рассылает
её компьютерам и телефону. Один файл ~6 МБ, занимает ~8 МБ оперативки.

- текст и ссылки (до 1 МБ), файлы **до 20 МБ** — байт в байт, без пережатия;
- файлы лежат в `/tmp/clipd` (оперативная память роутера, флеш не изнашивается),
  всего до **80 МБ**, самые старые удаляются первыми, любой файл удаляется через **24 ч**;
- после перезагрузки роутера буфер пустой — это нормально.

## Установка на роутер (с Windows)

1. Скачай `clipd-mt3000.tar.gz` в папку «Загрузки».
2. Открой **PowerShell** и выполни (пароль — тот же, что от админки роутера):
   ```powershell
   cd $HOME\Downloads
   scp -O clipd-mt3000.tar.gz root@192.168.8.1:/tmp/
   ssh root@192.168.8.1
   ```
   Если `scp` ругается на `-O` (`unknown option`) — запусти ту же команду без `-O`.
   При первом подключении на вопрос про `fingerprint` ответь `yes`.
3. Уже на роутере:
   ```sh
   cd /tmp && tar xzf clipd-mt3000.tar.gz && sh clipd-install/install.sh
   ```
4. Скрипт напечатает **токен** и ссылку. Открой в браузере на телефоне или ПК
   `http://clip.lan:8765` (или `http://192.168.8.1:8765`) и введи токен —
   это тестовая веб-страничка: можно отправлять текст и файлы и видеть всё, что пришло.

Обновление — те же шаги, настройки и токен сохраняются.
Удаление: `sh /tmp/clipd-install/uninstall.sh` (из распакованного архива).

## Полезные команды на роутере

```sh
logread -e clipd                 # журнал
/etc/init.d/clipd restart        # перезапуск
uci get clipd.main.token         # показать токен
uci set clipd.main.quota_mb=100 && uci commit clipd && /etc/init.d/clipd restart
```

Настройки в `/etc/config/clipd`: порт, токен, размер файла, квота, срок жизни файлов, длина истории.

## API (для клиентов)

Авторизация: заголовок `Authorization: Bearer <токен>` или параметр `?token=`.
Имя устройства: заголовок `X-Device` (URL-кодированный) или параметр `?device=`.

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/healthz` | проверка, без токена |
| `GET` | `/ws` | WebSocket: живые обновления (см. `hub.go`) |
| `GET` | `/api/items` | вся история (старые → новые) |
| `GET` | `/api/items/latest[?kind=text\|url\|file]` | последняя запись |
| `POST` | `/api/clip` | текст: `{"text":"…"}` или просто тело запроса |
| `PUT` | `/api/files?name=<имя>` | файл потоком в теле; опц. `X-Sha256` для проверки |
| `GET` | `/api/files/{id}` | скачать файл (поддерживает `Range`, `?inline=1`) |
| `DELETE` | `/api/items/{id}` | удалить запись |

Сообщения WebSocket (JSON):

```jsonc
// сервер → клиент
{"type":"hello","items":[…],"devices":["pc","s24"],"limits":{…}}
{"type":"clip","item":{"id":"…","kind":"file","from":"s24","ts":…,
  "file":{"name":"IMG.jpg","size":8421337,"mime":"image/jpeg","sha256":"…"}}}
{"type":"delete","id":"…"}
{"type":"devices","devices":["pc","laptop","s24"]}
// клиент → сервер
{"type":"clip","text":"…"}   {"type":"delete","id":"…"}   {"type":"ping"}
```

Запись может прийти и в `hello`, и отдельным `clip` — клиент убирает дубли по `id`.
Отправитель тоже получает свою запись обратно (это подтверждение).

## Разработка

```sh
go test -race ./...     # тесты
./build.sh              # dist/clipd-mt3000.tar.gz для роутера (linux/arm64)
go run . -data ./data -token dev   # локальный запуск: http://localhost:8765/#token=dev
```
